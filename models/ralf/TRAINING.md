# RALF Training

This document claims end-to-end package training reproduction for CGL unconditional conditioning and records the completed label, label-size, completion, and refinement campaigns. The unconditional claim is supported by the staged validation ladder defined in [Validation Stages](#validation-stages), three package/original-code seed pairs trained for 30 epochs, and the original evaluator's test protocol. Each package mean fell inside the corresponding original-code three-seed range for all 15 metrics. An independent rerun of the full vendor-parity test suite recorded 28 passed tests, 0 failed tests, and 0 skipped tests. The scheduler milestone is epoch 21, derived as `0.7 × 30` epochs.

The CGL label-conditioned and label-size-conditioned paths have completed their staged validation ladders and full-run evaluations; their evidence is recorded in [CGL label S5 comparison](#cgl-label-s5-comparison) and [CGL label-size S5 comparison](#cgl-label-size-s5-comparison). The CGL completion path, completion (vendor task `partial`), in which the layout is generated given its first element, also has staged validation and a five-seed full-run comparison recorded in [CGL completion S5 comparison](#cgl-completion-s5-comparison). Refinement, in which a noisy layout is corrected into a clean one, has the same S0-S5 evidence shape and is reproduced within the vendor's seed-to-seed variation; three of the 15 metrics fail the both-direction range test. CGL relation has accepted S0-S4 evidence and its authorized 5+5 S5 run is in progress; the final statistical comparison remains pending. The both-direction range test requires each system mean to lie within the other system's observed minimum-to-maximum range. PKU remains unclaimed.

## CGL refinement-conditioned training

This section records the pinned-code S0-S4 ladder, the clean-target S1/S2 rerun, and the five-package/five-vendor S5 comparison. The S5 status is `s5-practical-reproduction`.

The pinned public code trains the noisy layout as both condition and target. The clean-target reproduction tests the authors' published behavior by applying a one-line harness patch to vendor training and using clean teacher-forcing targets in the package; [Observed vendor behavior](#observed-vendor-behavior) explains the mechanism and evidence before the stage tables.

### Observed vendor behavior

At pinned vendor revision `c51db6032acbd0bd0ce72433becce08317e7874d`, refinement training uses the perturbed noisy layout as both condition and target. In `vendor/ralf/image2layout/train/helpers/task.py:152`, `get_condition` executes `batch[key] = new_batch[key].clone()`. Present since the vendor's first public commit `aae91db5f07976c9a8275dcef2dde41ba9ec1206`, the refinement branch draws CPU `torch.normal` noise in `GEO_KEYS` order, clamps it to `[0, 1]`, zeros padded elements, tokenizes `new_batch`, and performs that in-place assignment. `BaseAuxilaryTaskAutoreg.preprocess` in `vendor/ralf/image2layout/train/models/autoreg.py` then builds shifted targets from that mutated batch, while `RefinementPreprocessor.__call__` in `vendor/ralf/image2layout/train/models/layoutformerpp/task_preprocessor.py` consumes the same refinement condition for `seq_layout_const`. The real-batch evidence is `.cache/ralf/training-reproduction/cgl/refinement/s1/final-002/s1.json` (SHA-256 `6576b3269f1d0b992db916a5739d383e9bcb54edaa9467f8da3ccad4e2358f29`), which records the clean and noisy layouts, vendor target token IDs, and `target_is_shifted_noisy_sequence: true`. Under the pinned code, vendor-seed-1 and package-seed-1..5 train condition copiers: their FID is approximately `5.0`, and their layout-only metrics are bit-identical at printed precision. The harness-side one-line patch `.cache/ralf/training-reproduction/cgl/refinement/hypothesis/vendor-clean-target.patch` (SHA-256 `dd7de724ad19ac17bb80462c1d02c7d37a13ba0405b692bded5bfd1e425d6500`) removes only that assignment in the vendor working copy and restores the authors' published behavior. The reproduction target for this condition is therefore the authors' published behavior rather than the pinned public code as released. Evaluation is unaffected by this training-target choice: `vendor/ralf/scripts/run_job/eval_inference.sh:27-36` passes `cond_type=refinement test_split=test`, adds `sampling=deterministic` at lines 29-30, and then runs inference plus `eval.py` on the generated pickle files.

### CGL refinement S5 comparison

The question for this experiment is whether package refinement-conditioned training reproduces the authors' published behavior when the clean layout is teacher-forced and the noisy layout is supplied as the condition. The design used five matched package/vendor training seeds, the vendor's 35-epoch refinement recipe, the harness-side one-line vendor patch, the package clean-target path, the vendor inference path, and `eval.py` under the refinement condition. The result is that the clean-target reproduction is supported: vendor FID is `0.12564840864272733` to `0.13764282678530057`, package FID is `0.12638712407958033` to `0.16877349381038206`, and the authors' reference FID is `0.14299196227947655`; package/vendor means pass 12/15 both-direction range tests, with 0/15 Welch and 0/15 exact permutation p-values below `0.05`. The consequence is that the refinement comparison is reproduced within the vendor's seed-to-seed variation even though three range tests fail and neither significance test separates the systems.

The package and patched-vendor runs used training seeds 1-5, batch size `32`, the recipe epoch count returned by `_recipe_epochs("cgl", "refinement")` (`35`), learning rate `1e-4`, gradient clipping `0.1`, AdamW weight decay `1e-4`, and the vendor scheduler. Vendor training used the harness-side clean-target patch and `++generator.auxilary_task=refinement`; package training used clean teacher-forcing targets with noisy condition kwargs. Evaluation used `cond_type=refinement`, `test_split=test`, `sampling=deterministic` as added by `vendor/ralf/scripts/run_job/eval_inference.sh:29-30`, vendor defaults `refine_mode=uniform`, `refine_offset_ratio=0.1`, and `refine_lambda=3.0`, inference seeds `0/1/2`, and all 15 values from `average.test`. The earlier top-k evaluations are retained under `superseded-top_k/` and are excluded. The both-direction range test means that the package mean lies within the vendor minimum-to-maximum range and the vendor mean lies within the package minimum-to-maximum range; Welch p is the two-sided unequal-variance test, and permutation p is the two-sided exact fraction of all `C(10,5)=252` relabelings whose absolute package-vendor mean difference is at least the observed difference, with means computed as `Fraction(str(value))` from the recorded decimal scores.

### Relation condition and evaluation contract

During training, the pinned vendor's `helpers/task.py` `relation` branch loads the relationship dictionary at `$RALF_CACHE_DIR/pku_cgl_relationships_dic_using_canvas_sort_label_lexico.pt` and builds a sampled relation graph. The sequence is therefore sampled rather than deterministic in isolation. Vendor `set_seed` seeds the stdlib stream. The package consumes the same stdlib `random` calls, in the same order and with the same sizes, including the construction-time list shuffle and per-batch subset selection; the harness reseeds immediately before preprocessor construction and before each package/vendor batch condition. That is how S1 obtained exact relation token and pad-mask parity and zero per-token loss difference.

Evaluation follows `vendor/ralf/scripts/run_job/eval_inference.sh` without a relation-specific extra flag. In `inference.py` around lines 326-336, backtracking is enabled when `cond_type=relation`. ### CGL label-size S5 comparison

The question for this experiment is whether package label-size training reproduces the vendor's label-size training. The design used five matched training seeds per system, the vendor's 40-epoch category, width, height conditioning (`cwh`) recipe, in which the layout is generated given each element's category and size, the vendor's own inference path, and the vendor's own evaluator. The result is that no metric separates the systems under the prespecified checks: 12/15 metrics pass the both-direction range test, 0/15 have Welch p<0.05, 0/15 have exact permutation p<0.05, and the largest standardized difference is 1.37 on `overlap-LayoutGAN++`. The maintainer assigns the reproduction verdict.

The package and vendor runs used training seeds 1-5, batch size 32, learning rate `1e-4`, gradient clipping `0.1`, AdamW weight decay `1e-4`, and scheduler milestone 28. ### Control experiment: original vs original

The purpose is to establish the original implementation's own run-to-run noise floor under the exact both-direction range test and Welch protocol, so the label S5 result can be judged against how well the original reproduces itself.

Noise floor means the variation measured when the same original implementation is trained and evaluated again with the same recipe, while only the training seed changes. Vendor A is the original implementation with training seeds 1 through 5, and vendor B is the original implementation with training seeds 6 through 10.

For the both-direction range test, the first group's mean must be within the second group's inclusive minimum-to-maximum range, and the second group's mean must also be within the first group's range. Welch p is the two-sided unequal-variance t-test for the two seed groups. The permutation failure probability is the exact fraction of relabelings of the pooled values, preserving both group sizes, for which the same both-direction range test fails.

All five control trainings reached epoch 50/50 and all five original-protocol evaluations returned PASS. All five control runs completed without restart.
