# Layout-Corrector Training

The staged package/original-code evidence passes for RICO25 and PubLayNet at training seed 42975 and evaluation seed 0/314159 as recorded below. Natural production-path S3 is bitwise for 300 steps on both datasets, so the synchronized S3 layer is not-needed. S4 covers the 16-worker loader stream and the original evaluation entry point with retained vendor outputs. S5 is `not-yet-run (https://github.com/creative-graphic-design/design-generators/issues/426)`.

Run commands from the repository root. Generated data, logs, checkpoints, converted local pipelines, and evaluation artifacts stay under `.cache/layout-corrector/` or the explicitly named local audit/evaluation roots.

## Install

The repository environment and the training extra are synchronized with:

```bash
UV_FROZEN=1 uv sync --package layout-corrector --extra training
```

The one deliberate lockfile-generation command for the `training` extra was:

```bash
uv lock
```

## Scheduler and Recipe Notes

The vendor training entry point is `vendor/layout-corrector/bin/corrector_train.sh`; its effective training path is exposed through the original corrector module. The package path uses `LayoutCorrectorTrainingModule.training_step` and `configure_optimizers` under Lightning. Both use AdamW with learning rate `5.0e-4`, betas `(0.9, 0.98)`, weight decay `0.1`, gradient clipping at norm `1.0`, batch size `64`, and `ReduceLROnPlateau` with factor `0.5`, patience `2`, threshold `0.01`, and epoch cadence.

The S0-S3 runs use the importance-sampled corruption branch, 16 loader workers, CUDA device 0, 32-bit arithmetic, `CUBLAS_WORKSPACE_CONFIG=:4096:8`, `torch.use_deterministic_algorithms=False`, and `cudnn.deterministic=False`. Initialization follows the original entry-point order: set the seed, build diffusion, then build the corrector. The package initialization-device assertion and complete parameter-registration-order assertion are CPU-tested.

The shared LayoutDM sampling behavior used by the evidence includes the vendor's `log(1e-30)` posterior floor and vocabulary-axis softmax/reduction before flattening. The S4 evaluation uses `vendor/layout-corrector/bin/corrector_test_eval.py`, which routes to `corrector_test`, with `corrector_t_list=[10,20,30]`, conditions `unconditional`, `c`, and `cwh`, no Gumbel noise, 100 diffusion steps, batch size 512, and seed 0. The vendor output files are retained outputs from sweep source commit `5ee3af2`; only the package comparison and `bin/calc_metrics.py` are rerun for this evidence. PubLayNet has 11,142 TEST layouts; its unconditional sweep count is 1,000 because the vendor `corrector_test` configuration uses `num_uncond_samples=1000`, while `c` and `cwh` evaluate the full TEST layout set.

## Seed Policy

S0 initialization uses seed 123. Natural S1-S3 training evidence uses training seed 42975, with each system's production RNG path and no per-step RNG restore or injected shared random tensors. S4 retained-output evaluation uses seed 0, and the loader-stream evidence uses control seed 314159. S5 has no training-seed comparison.

## Training Commands

Initialize the vendor submodules and run the package training recipe with the locked training extra:

```bash
git submodule update --init vendor/layout-corrector vendor/layout-dm
CUDA_VISIBLE_DEVICES=<gpu-index> UV_FROZEN=1 uv run --package layout-corrector --extra training traingen fit --config models/layout-corrector/configs/training/layoutcorrector_<rico25|publaynet>.yaml --trainer.devices=1
```

Run the staged parity suite with local assets and `PARITY_REQUIRE=1`:

```bash
CUDA_VISIBLE_DEVICES=<gpu-index> UV_FROZEN=1 uv run --package layout-corrector --extra training --extra vendor pytest models/layout-corrector/tests/vendor_parity -m 'vendor_parity and training' -rs
```

Convert a trained checkpoint and smoke-test package loading with `from_pretrained`:

```bash
UV_FROZEN=1 uv run --package layout-corrector --extra convert models/layout-corrector/scripts/convert_original_checkpoint.py --checkpoint .cache/layout-corrector/training-runs/<dataset>/checkpoints/<checkpoint>.ckpt --output-dir .cache/layout-corrector/converted-trained/<dataset>
UV_FROZEN=1 uv run --package layout-corrector python - <<'PY'
from layout_corrector import LayoutCorrectorPipeline

pipe = LayoutCorrectorPipeline.from_pretrained('.cache/layout-corrector/converted-trained/<dataset>')
output = pipe(condition_type='unconditional', num_inference_steps=2)
print(output.bbox.shape, output.labels.shape, output.mask.shape)
PY
```
