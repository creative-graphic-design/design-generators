# RADM Training

This document records the package-local checks that contributors can rerun before deciding whether RADM full training may be claimed.

## Result at a glance

The RADM package passes the final S0-S4 checks, the current-head evaluation-path parity prerequisite, and the natural S3 package/vendor layer. The CGL S5 result is `blocked (package training stream differed from the original at the launch commit — sampler/aspect-ratio grouping — corrected and verified by the full-stream S4; the target-transform clipping operation was corrected and verified by the full-stream S4; the timestep dtype path was corrected and verified by the fixed-head time-embedding regression test; the bbox-delta expression was corrected and verified by its regression test; the RoI-layout operation was corrected and verified by its stride regression test; vendor head initialization was corrected and verified by the fail-closed initializer-scheme test over 445 parameter rows; full-model clipping under Lightning automatic optimization is now applied and verified by `test_lightning_optimizer_clips_current_step_gradient`; the f949974 retrain predates that fix)`. The retained diagnosis checkpoints came from the invalid launch stream, so they are not S5 reproduction evidence. CGL-v2 is outside the approved S5 scope. No vendor-parity verification claim is made.

The retained six-checkpoint diagnosis uses the regenerated fixed equivalent evaluator on the invalid-stream runs, but those six prediction files were produced before the five package inference/data-path fixes listed below; they diagnose the earlier training run and are not current-head inference evidence. The headline directional shift is in `R_ove`, `R_und`, and prediction count. `R_ali` and `R_occ` ranges overlap. `R_com` has separated three-value ranges under the descriptive criterion stated below. These report-only observations do not establish training equivalence or non-equivalence.

The current-head evaluation-path comparison covers one shared original seed-1 checkpoint. The package and vendor each produce `4,635` predictions; image/category ids and scores match exactly, boxes match at absolute tolerance `0.0001`, all metrics match at absolute tolerance `2e-9`, and both out-of-bounds counts are `1` under the stated `1e-6` rule. This is an evaluation-path prerequisite pass, not full training parity.

## Install

Run commands from the repository root. Keep generated data, logs, checkpoints, converted local pipelines, and evaluation artifacts under `.cache/radm/`.

```bash
uv sync --package radm --extra training
```

Install the `vendor` extra only for original-code parity checks.

```bash
uv sync --package radm --extra training --extra vendor
```

## Scheduler and recipe notes

The effective recipe uses AdamW with learning rate `2.5e-5`, weight decay `1e-4`, batch size `16`, full-model gradient clipping at `1.0`, warmup factor `0.01` for `1,000` optimizer steps, milestones `150,000` and `220,000`, maximum `250,000` optimizer steps, `1,000` diffusion timesteps, `SNR_SCALE=2.0`, `SAMPLE_STEP=1`, `100` proposals, six repeated heads, and FP32 arithmetic. The package optimizer owns clipping: Lightning keeps `gradient_clip_val=0.0`, and the optimizer runs the automatic-optimization closure before clipping the current full-model gradient once.

The scheduler is checked at optimizer-step cadence. The timestep sampler is checked in the fixed-batch and multi-batch traces. EMA and AMP do not apply to the recorded loop. The approved parity configuration uses `num_workers=0`.

The retained S0 topology evidence records that text encoding fields are derived from the selected mapper, with class-mapping and derived-output guards active; the accepted topology run recorded `23 passed` with artifact `413f87a45760ceac5635b6a08c8047f86478acf5`. The fixed-head S0 initializer-scheme test `test_s0_radm_init_scheme_matches_vendor` compares `445` mapped parameter rows and records `0` mismatches; every package/vendor row uses the same initializer scheme and arguments. The head fix now executes the vendor `xavier_uniform_`, focal-prior, GRAM/final-layer, and time-MLP initialization calls at the same construction point and in the same order, so the earlier initialization call-order deviation is withdrawn.

The issue 261 amendment defines the pre-S5 lockstep gate for this model: initial state, RNG and batch alignment, step-1 forward and loss surfaces, and the recorded step-1 gradient tolerance must pass. Natural long-run comparisons are report-only. The amendment is [issue 261 comment 5318097501](https://github.com/creative-graphic-design/design-generators/issues/261#issuecomment-5318097501).

### Before any S5 launch

The launch prerequisites are measured and recorded: the nested S4 stream passes over `3,784` batches and `60,544` images; the mapper oracle matches post-transform XYXY clipping to resized bounds while preserving vendor resize-coordinate truncation; current-head evaluation-path parity passes with `4,635` predictions on each side and equal metrics; the natural `300`-step separate-process self-repeats are bitwise equal within each system; and the synchronized `300`-step lockstep is bitwise equal. Periodic vendor evaluation is disabled during package training; the shipped package config has no vendor evaluator hook. The launch manifest is written before the seed queue and records the source commit, resolved shipped config, evaluator command, checkpoint rule, runtime, worker count, and artifact hashes. The source-commit gate was exercised with a deliberate mismatch dry run and stops before training when the pinned commit differs. Tests marked `vendor_parity` are excluded from regular member-test runs; the CPU regression tests for automatic-optimization clipping, configuration round-trip, and RoI layout run in the regular member suite.

## Seed policy

S0-S4 fixtures use the recorded parity seed and are not training-seed or evaluation-seed results. The retained CGL diagnosis covers paired training labels `1`, `2`, and `3` per system and is invalid-stream evidence, not an S5 result. The shared-weight evaluation-path check uses evaluation seed `1`.

The package and vendor use uniform shuffles of the same population for each epoch with the same sampler behavior; the accepted aspect-ratio-grouping fix is covered by S4, and the mapped streams match under a shared seed. The earlier seed-policy deviation note is withdrawn: after the head fix, package and vendor execute the same vendor head initialization path at the same construction point, and the prior call-order shift no longer produces different values. The natural S3 layer is bitwise `PASS`: `669` mapped final model rows and `434` mapped optimizer rows have no missing or extra entries, maximum absolute and relative differences `0.0`, and no first differing row; each system's separate-process self-repeat is equal for all `300` steps. The S5 statistical design remains three package versus three vendor training seeds, with the range test and seed-spread comparison unaffected.
