# RADM Training

This document records the package-local checks that contributors can rerun before deciding whether RADM full training may be claimed.

## Result at a glance

The RADM package passes the final S0-S4 checks and the evaluation-path parity prerequisite. The CGL S5 result is `blocked (package training stream differed from the original at the launch commit — sampler/aspect-ratio grouping — corrected and verified by the full-stream S4; the target-transform clipping operation was corrected and verified by the full-stream S4; the timestep dtype path was corrected and verified by the fixed-head time-embedding regression test; retrain pending)`. The retained package checkpoints came from the invalid launch stream, so this PR does not retrain them. CGL-v2 is outside the approved S5 scope. No S5 reproduction or vendor-parity verification claim is made.

The retained six-checkpoint diagnosis uses the regenerated fixed equivalent evaluator on the invalid-stream runs. The headline directional shift is in `R_ove`, `R_und`, and prediction count. `R_ali` and `R_occ` ranges overlap. `R_com` has separated three-value ranges under the descriptive criterion stated below. These report-only observations do not establish training equivalence or non-equivalence.

The evaluation-path parity prerequisite passes for one shared original seed-1 checkpoint. It uses stated prediction and metric tolerances and reports the vendor's one out-of-bounds prediction separately from the package's zero under the stated rule. This is a path check, not full training parity.

## Install

Run commands from the repository root. Keep generated data, logs, checkpoints, converted local pipelines, and evaluation artifacts under `.cache/radm/`.

```bash
uv sync --package radm --extra training
```

Install the `vendor` extra only for original-code parity checks.

```bash
uv sync --package radm --extra training --extra vendor
```

## Scheduler and recipe notes

The effective recipe uses AdamW with learning rate `2.5e-5`, weight decay `1e-4`, batch size `16`, full-model gradient clipping at `1.0`, warmup factor `0.01` for `1,000` optimizer steps, milestones `150,000` and `220,000`, maximum `250,000` optimizer steps, `1,000` diffusion timesteps, `SNR_SCALE=2.0`, `SAMPLE_STEP=1`, `100` proposals, six repeated heads, and FP32 arithmetic.

The scheduler is checked at optimizer-step cadence. The timestep sampler is checked in the fixed-batch and multi-batch traces. EMA and AMP do not apply to the recorded loop. The approved parity configuration uses `num_workers=0`.

The retained S0 topology evidence records that text encoding fields are derived from the selected mapper, with class-mapping and derived-output guards active; `test_s0_radm_topology.py` was part of the retained `23 passed` result against vendor revision `413f87a45760ceac5635b6a08c8047f86478acf5`.

The issue 261 amendment defines the pre-S5 lockstep gate for this model: initial state, RNG and batch alignment, step-1 forward and loss surfaces, and the recorded step-1 gradient tolerance must pass. Natural long-run comparisons are report-only. The amendment is [issue 261 comment 5318097501](https://github.com/creative-graphic-design/design-generators/issues/261#issuecomment-5318097501).

### Before any S5 launch

Before a future S5 launch, complete these checks and retain their outputs:

- Run the full-stream S4 check with the vendor's seeded sampler, aspect-ratio grouping, worker count, and full-batch policy.
- Run the vendor-mapper oracle and confirm that post-transform clipping of XYXY target coordinates to the resized image bounds matches Detectron2 `transform_instance_annotations`; resize-coordinate truncation must remain the vendor behavior.
- Rerun evaluation-path parity on the launch weights with the vendor evaluator and the package evaluator, including prediction and metric tolerances and the out-of-bounds rule.
- Repeat the natural separate-process comparison and synchronized lockstep after every training-path change. The current package and vendor trajectory-1 records are bitwise equal across two processes, and the current synchronized lockstep is bitwise equal for `300` steps. The earlier within-process pair figures are withdrawn because the driver reused state inside one process.
- Decide whether periodic vendor evaluations that consume the vendor RNG stream are enabled, and record the choice before launch.
- Write the launch manifest before launching the seed queue. The manifest must identify the source commit, resolved configuration, evaluator command, checkpoint rule, artifact hashes, and launch time.
- Confirm that the launch queue stops when its source-commit gate fails in a deliberate mismatch dry run.

The current PR does not launch another S5 queue or retrain a seed.

### S3 classification

The separate-process comparison `.cache/radm/s3/run-070-cross-process-comparison.json` records package trajectory 1 versus trajectory 1 from a second process as bitwise equal for `3` steps, and the same result for the vendor. The package and vendor are therefore run-to-run deterministic under this recorded launch. The earlier within-process pair figures are withdrawn because that driver reused state inside one process; they are not evidence of cross-process behavior.

The synchronized lockstep `.cache/radm/s5-preflight/run-071-gpu4-20261008/lockstep-300.jsonl` records initial state bitwise equality and no first divergence over `300` steps. S3 is `natural: bitwise equal separate-process trajectory-1 comparisons; synchronized: bitwise lockstep for 300 steps`. This establishes exact agreement for the recorded inputs, runtime, and step population. It does not establish S5 training reproduction or agreement beyond the recorded population.

The final parity work corrected four package operations and pinned each correction with a regression check. The target path now performs post-transform clipping of XYXY target coordinates to the resized image bounds, mirroring Detectron2 `transform_instance_annotations` after `apply_box`, with resize-coordinate truncation preserved; `test_s4_aligned_train_mapper_fixture_matches_vendor` and the nested S4 stream gate pin it. The time path now passes vendor `int64` timesteps directly into the time MLP; `test_time_embedding_keeps_vendor_integer_timestep_path` compares the fixed timestep batch bitwise with the vendor embedding. The bbox-delta path now follows the vendor's indexed `0::4` extraction, pre-exponential `dw` and `dh` clamp, width/height multiplication, and indexed writes into a zero tensor; `test_box_delta_expression_matches_vendor_source` pins that output. The ROI path now preserves the vendor channels-last allocation at the pooling output and fills level-selected rows with `index_put_`; the lockstep regression asserts the vendor and package output stride `[12544, 1, 1792, 256]` and bitwise values. These are package fixes.

The S1-S3 fixtures feed batches through the vendor `dataset_mapper`; they bypass the changed package mapper path, which is exercised by the S4 full-stream comparison and mapper-oracle test. The four fixes and their tests are covered by ancestor commits `49544780e4cd98fd990fc03e08aec9108db5e2a6`, `d1d596db6fab41178a8d60d9bb98a16cb0ad18c5`, `63837415c53d0b14eaaa2fb9c117f816895ebfc8`, and `722bdd55fdeb9c9afbb489e84075a91eef666c30`.
