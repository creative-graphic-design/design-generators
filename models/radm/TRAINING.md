# RADM Training

This record covers the launch configuration and launch evidence for six RADM CGL runs. The package and original runs (training seeds 1–3) launched from commit `4e5c31d44052ae0f8f682c073ba6ab9d940be503` on 2026-11-06 JST and completed later. Their terminal comparison is not recorded here yet. No CGL S5 result is claimed. See [RADM CGL training design](https://github.com/creative-graphic-design/design-generators/issues/261) for the training scope.

## Result at a glance

The original RADM mapper derives text-feature filenames from the visible image path, so dots in a data-root path can make valid text features unreachable. Text-conditioned pre-launch checks passed from source commit `4e5c31d44052ae0f8f682c073ba6ab9d940be503`. The checks included a 300-step real-CGL lockstep, the three-seed 1,500-update loss envelope for both arms, S4 train/test text parity, evaluation-path parity, and a two-step top-k checkpoint smoke. Six full-run training jobs (package and original, training seeds 1–3) launched on 2026-11-06 JST from that same commit and completed. Their terminal comparison is not recorded in this document yet. Earlier textless CGL S3/S4/evaluation evidence and original S5 results remain below as historical, superseded records.

The earlier evaluation-path comparison covers one shared original seed-1 checkpoint. It produced `4,635` predictions per side with matching ids, scores, boxes, and metrics, but the source path loaded no text features. That comparison is superseded by the text-conditioned evaluation-path check recorded below. The current package evaluator reads CGL test features. `test_package_checkpoint_evaluator_reads_test_text_features` (`models/radm/tests/vendor_parity/test_s5_evaluation_end_to_end.py#L225`; vendor_parity, not run by default) verifies this. `test_vendor_evaluator_command_uses_absolute_visible_data_root` (`models/radm/tests/vendor_parity/test_s5_evaluation_end_to_end.py#L251`; vendor_parity, not run by default) checks the vendor command. It sets `DATASETS.TEXT_FEATURE_PATH` to the absolute visible root's `text_features` directory.

## Install

Run commands from the repository root. Keep generated data, logs, checkpoints, converted local pipelines, and evaluation artifacts under `.cache/radm/`.

```bash
uv sync --package radm --extra training
```

Install the `vendor` extra only for original-code parity checks.

```bash
uv sync --package radm --extra training --extra vendor
```

## Data

The approved source for CGL is `creative-graphic-design/CGL-Dataset`, under the [shared source-selection rules](https://github.com/creative-graphic-design/design-generators/blob/main/docs/data-sources.md#shared-source-selection-rules). Its archive may be stored under `.cache/radm/data/cgl/` with source annotations, images, and text features. For original-code runs, pass a dot-free visible path string to the dataset root; a dot-free symlink alias is valid even when its target contains `.cache`, and the alias must not be resolved before it reaches the vendor mapper. The S5 launcher rejects any data-root component containing a dot. For images that genuinely have no feature file, training uses the vendor's all-padding zero-feature fallback. Package and original-code runs use the source five-label order and the released four-output-class configuration.

The visible alias behavior is checked by `test_dot_free_data_root_makes_relative_alias_absolute_without_resolving` (`models/radm/tests/test_training_data_paths.py#L177`). `test_dot_free_data_root_rejects_dotted_components` (`models/radm/tests/test_training_data_paths.py#L197`) rejects dotted components. Both arms receive the same absolute alias, checked by `test_s5_launcher_builds_same_absolute_data_root_for_both_arms` (`models/radm/tests/test_training_data_paths.py#L227`).

For a missing feature file, the package returns all-zero features with an all-padding mask. `test_missing_text_features_use_zero_features_and_padding_mask` (`models/radm/tests/test_training_data_paths.py#L207`) checks the CPU fallback values, mask, and shapes. The real mapper comparison is recorded as `fallback_equal` in the S4 result. Separately, `test_s4_radm_loader_stream_parity` (`models/radm/tests/vendor_parity/test_s4_radm_loader_stream.py#L693`; vendor_parity, not run by default) checks the full loader stream. The five-label vocabulary and four output classes are checked by `test_s0_effective_config_exposes_four_class_five_label_discrepancy` (`models/radm/tests/test_training_s0_contracts.py#L331`).

Training RoI inputs scale normalized boxes before casting to float32. `test_training_rois_match_vendor_scale_then_float32_order` (`models/radm/tests/test_training_surfaces.py#L422`) checks the order.

### Backbone initialization

The CGL and CGL-v2 training recipes select Detectron2's converted torchvision ImageNet R-50 artifact at the [stable public URL](https://dl.fbaipublicfiles.com/detectron2/ImageNetPretrained/torchvision/R-50.pkl); its SHA-256 is checked before loading. The official [Detectron2 conversion script](https://github.com/facebookresearch/detectron2/blob/main/tools/convert-torchvision-to-d2.py) names `resnet50-19c8e357.pth` as its source and maps the torchvision checkpoint into Detectron2 keys, so the matching torchvision ImageNet V1 tensors are equivalent after that key conversion. The current torchvision `DEFAULT` alias is V2; the distinct Detectron2 `ImageNetPretrained/MSRA/R-50.pkl` artifact uses the MSRA/Caffe weights. Neither is a substitute for the pinned torchvision artifact. The official [TorchVision ResNet-50 weights page](https://docs.pytorch.org/vision/stable/models/generated/torchvision.models.resnet50.html) documents the V1/V2 distinction. The [Detectron2 Model Zoo](https://github.com/facebookresearch/detectron2/blob/main/MODEL_ZOO.md#imagenet-pretrained-models) lists the artifact under [CC BY-SA 3.0](https://creativecommons.org/licenses/by-sa/3.0/), which requires attribution and ShareAlike when redistributing the weights or adaptations; package training downloads it into the local cache and does not commit or republish it. The package maps all `265` ResNet body tensors to package keys and leaves FPN initialization unchanged. RGB input uses pixel mean `[123.675, 116.280, 103.530]` and standard deviation `[58.395, 57.120, 57.375]`, with `STRIDE_IN_1X1=False`, matching the torchvision conversion convention. The default cache path is `.cache/radm/weights/R-50.pkl`; select another path with `model.init_args.pretrained_backbone_weights`.

The converted ResNet body tensors are checked by `test_s0_training_module_initializes_backbone_from_converted_r50`. See `models/radm/tests/vendor_parity/test_radm_pretrained_backbone.py#L45` (vendor_parity, not run by default). FPN initialization preservation is checked by `test_load_pretrained_r50_maps_resnet_and_keeps_fpn_initialization` (`models/radm/tests/test_pretrained.py#L69`).

## Scheduler and recipe notes

The effective recipe uses AdamW with learning rate `2.5e-5`, weight decay `1e-4`, batch size `16`, full-model gradient clipping at `1.0`, warmup factor `0.01` for `1,000` optimizer steps, milestones `150,000` and `220,000`, maximum `250,000` optimizer steps, `1,000` diffusion timesteps, `SNR_SCALE=2.0`, `SAMPLE_STEP=1`, `100` proposals, six repeated heads, and FP32 arithmetic. The package optimizer owns clipping: Lightning keeps `gradient_clip_val=0.0`, and the optimizer runs the automatic-optimization closure before clipping the current full-model gradient once.

The effective-config check covers the optimizer, learning rate, weight decay, clip norm, warmup iterations, milestones, maximum iteration count, batch size, and worker count. `test_s0_effective_config_captures_optimizer_scheduler_and_sampler_state` (`models/radm/tests/test_training_s0_contracts.py#L352`) verifies these fields. `test_s0_optimizer_is_the_only_gradient_clipping_owner` (`models/radm/tests/test_training_s0_contracts.py#L199`) checks that the optimizer owns clipping.

The current Lightning clipping path is checked by `test_lightning_optimizer_clips_current_step_gradient` (`models/radm/tests/test_training_gradient_clipping.py#L89`).

The scheduler is checked at optimizer-step cadence. `test_optimizer_scheduler_parity_and_training_module_paths` (`models/radm/tests/test_training_surfaces.py#L347`) checks the interval. The timestep sampler is checked in the fixed-batch and multi-batch traces. `test_s1_radm_fixed_batch_pre_optimizer_parity` compares source and package timestep tensors (`models/radm/tests/vendor_parity/test_s1_radm_training.py#L1796`; vendor_parity, not run by default). The multi-batch `test_s3_radm_deterministic_multi_batch_parity` records per-step RNG states, not sampled timestep values. `models/radm/tests/vendor_parity/test_s1_radm_training.py#L2216` is vendor_parity, not run by default. EMA and AMP do not apply to the recorded loop. The parity configuration uses `num_workers=0`.

`test_s0_radm_topology` (`models/radm/tests/vendor_parity/test_s0_radm_topology.py#L174`; vendor_parity, not run by default) compares EMA and AMP runtime state with the reference.

The retained S0 topology evidence records that text encoding fields are derived from the selected mapper, with class-mapping and derived-output guards active. The topology run recorded `23 passed` with artifact `413f87a45760ceac5635b6a08c8047f86478acf5`. The current topology gate is `test_s0_radm_topology` (`models/radm/tests/vendor_parity/test_s0_radm_topology.py#L174`; vendor*parity, not run by default). The fixed-head S0 initializer-scheme test is `test_s0_radm_init_scheme_matches_vendor` (`models/radm/tests/vendor_parity/test_s0_radm_topology.py#L223`; vendor_parity, not run by default). It compares `445` mapped parameter rows and records `0` mismatches. Every package/vendor row uses the same initializer scheme and arguments. The head fix now executes the vendor `xavier_uniform*`, focal-prior, GRAM/final-layer, and time-MLP initialization calls at the same construction point and in the same order. The earlier initialization call-order deviation is withdrawn.

The pre-S5 lockstep gate requires equal initial state, aligned RNG and batches, matching step-1 forward and loss surfaces, and a passing step-1 gradient tolerance. Natural long-run comparisons are report-only. The lockstep criterion is recorded in the [issue 261 lockstep amendment](https://github.com/creative-graphic-design/design-generators/issues/261#issuecomment-5318097501).

Production CGL runs use `trainer.deterministic: false`; deterministic controls remain enabled for the parity lockstep. The 60.016-second package measurement over updates 301–341 recorded `1.500405` seconds per update and did not meet the [GPU-bound criterion](https://github.com/creative-graphic-design/design-generators/blob/main/docs/training-reproduction.md#gpu-placement). The measurement is `.cache/radm/s5/cgl/prelaunch-4e5c31d/gpu-bound/seed-1-steps300-500.json` (SHA-256 `3b58a296b2f450a201272d7ab34cf494d5e568091a58c6ef00fd7a6f8e91a9e2`), with the run log at `.cache/radm/s5/cgl/prelaunch-4e5c31d/logs/gpu-bound-seed1.log` (SHA-256 `61ae87225c7a2bec62d050cd63e4c5f340aa9142fc106db097fc9b7dba5c06d5`). Package S5 seeds 1–3 ran under the GPU-bound deviation (see [recipe amendment](https://github.com/creative-graphic-design/design-generators/issues/261#issuecomment-6675591463)).

The production config behavior is checked by `test_s0_cgl_production_config_disables_deterministic_algorithms` (`models/radm/tests/test_training_s0_contracts.py#L55`).

- The pre-launch checks passed with one shared dot-free data-root path and source commit `4e5c31d44052ae0f8f682c073ba6ab9d940be503`. The Stage Evidence table lists their commands and artifacts.
- Six package and original CGL runs with training seeds 1–3 launched from that commit and completed later; their terminal comparison is not recorded in this document yet. See [RADM CGL training design](https://github.com/creative-graphic-design/design-generators/issues/261) for the training scope.
- Launches from this revision onward record both source revisions and resolved paths for all five workspace packages. They also record configuration identity and evaluator and checkpoint rules. `test_s5_launcher_writes_manifest_before_training` (`models/radm/tests/test_training_data_paths.py#L452`) checks the workspace path maps in `manifest.json` and `validation.json`. It asserts the exact keys `radm`, `laygen`, `posgen`, `traingen`, and `traingen_parity`. It verifies that every path resolves inside the checkout and that the manifest exists before training.
- New manifests record runtime versions, CUDA and GPU details, worker and thread counts, data-root hashes, text-feature counts, artifact hashes, and launch time. Their evaluator commands use absolute environment paths. The evaluator writes its checkout commit and working-tree status to the validation record; evaluator checkout identity is not a launch-manifest field.
- The six recorded launch manifests lack the evaluation-path parity artifact path and SHA-256 in `artifacts`. The training reproduction protocol requires both for every S5 launch. See the [evaluation-path parity prerequisite](https://github.com/creative-graphic-design/design-generators/blob/main/docs/training-reproduction.md#evaluation-path-parity-prerequisite). The [existing recipe amendment](https://github.com/creative-graphic-design/design-generators/issues/261#issuecomment-6675591463) records launch order; it does not record this missing artifact entry. A terminal amendment on [issue 261](https://github.com/creative-graphic-design/design-generators/issues/261) must record the missing launch evidence. Current launches reject a missing artifact argument, as `test_s5_launcher_requires_evaluation_path_parity_artifact` (`models/radm/tests/test_training_data_paths.py#L1082`) verifies.
- The tracked `sitecustomize.py` restores `PIL.Image.LINEAR` before Detectron2 imports it for original-code training and evaluation. `test_original_arm_manifest_records_the_tracked_compatibility_module` (`models/radm/tests/test_training_data_paths.py#L315`) checks the module setup.
- Regular member tests exclude modules marked `vendor_parity`. The regular suite covers CPU regressions for automatic-optimization clipping, configuration round-trip, and RoI layout.

## Seed policy

S0-S4 fixtures use the recorded parity seed and are not training-seed or evaluation-seed results. The retained CGL diagnosis covers paired training labels `1`, `2`, and `3` per system and is invalid-stream evidence, not an S5 result. The shared-weight evaluation-path check uses evaluation seed `1`.

The package and vendor use uniform shuffles with the same sampler behavior, and the aspect-ratio-grouping fix remains covered by the S4 regression code. `test_s4_radm_loader_stream_parity` (`models/radm/tests/vendor_parity/test_s4_radm_loader_stream.py#L693`; vendor_parity, not run by default) checks package/vendor loader-stream parity. `test_s0_training_sampler_matches_seeded_grouped_full_batches` (`models/radm/tests/test_training_s0_contracts.py#L823`) checks the package's seeded aspect-ratio batch sampler. Earlier real-CGL natural and synchronized S3 comparisons used a dotted source data path and remain superseded; the current text-conditioned lockstep and loss envelope are recorded in Stage Evidence. The S5 statistical design remains three package versus three original training seeds, with the range test and seed-spread comparison unchanged.

## Training commands

Run the staged parity checks with the audited runtime used for the final CUDA evidence.

```bash
CUDA_VISIBLE_DEVICES=<device> RADM_REFERENCE_DEVICE=cuda PARITY_REQUIRE=1 UV_FROZEN=1 "$RADM_REFERENCE_VENV/bin/python" -m pytest models/radm/tests/vendor_parity -m "vendor_parity and training" -rs
```

Run both CGL S5 arms from the same source commit and dot-free data-root string. The launcher converts a relative path to an absolute path lexically, then passes that same path to either arm without resolving symlinks; a dot-free alias may point into `.cache`. Before training starts, it requires clean repository and vendor source trees, verifies that the checked-out RADM vendor commit matches the root gitlink, requires annotation-matched text features in both splits and an available CUDA device, and refuses an existing output directory. From this revision onward, it writes `manifest.json` before training with both source revisions, resolved source paths for all five workspace packages, the named evaluation-path parity artifact path and SHA-256, arm config and SHA-256, evaluator and terminal-checkpoint rules, runtime versions, CUDA/GPU and thread details, worker count, hashes for the data-root alias and target, per-split feature counts, the original-arm Pillow compatibility module and SHA-256, and a timezone-aware launch time. The evaluator checkout commit and working-tree status go in `validation.json`, not the launch manifest. The tracked `sitecustomize.py` restores `PIL.Image.LINEAR` before Detectron2 imports it in the original training and evaluation processes. Repeat for each training seed and use a new output directory for every arm/seed pair.

The source preflight is checked by `test_s5_source_tree_must_be_clean_and_vendor_must_match_gitlink` (`models/radm/tests/test_training_data_paths.py#L797`). The text-feature preflight is checked by `test_empty_text_feature_splits_fail_before_subprocess` (`models/radm/tests/test_training_data_paths.py#L1156`).

```bash
set -euo pipefail
export SOURCE_COMMIT="$(git rev-parse HEAD)"
# Replace both values with the artifact generated for this source commit.
```
