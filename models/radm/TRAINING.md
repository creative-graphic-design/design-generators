# RADM Training

This document records the package-local checks that contributors can rerun before deciding whether RADM full training may be claimed.

## Result at a glance

The RADM package passes the final S0-S4 checks and the current-head evaluation-path parity prerequisite. The CGL S5 result is `blocked (package training stream differed from the original at the launch commit — sampler/aspect-ratio grouping — corrected and verified by the full-stream S4; the target-transform clipping operation was corrected and verified by the full-stream S4; the timestep dtype path was corrected and verified by the fixed-head time-embedding regression test; the bbox-delta expression was corrected and verified by its regression test; the RoI-layout operation was corrected and verified by its stride regression test; retrain pending)`. The retained diagnosis checkpoints came from the invalid launch stream, so they are not S5 reproduction evidence. CGL-v2 is outside the approved S5 scope. No vendor-parity verification claim is made.

The retained six-checkpoint diagnosis uses the regenerated fixed equivalent evaluator on the invalid-stream runs, but those six prediction files were produced before the four package inference/data-path fixes listed below; they diagnose the earlier training run and are not current-head inference evidence. The headline directional shift is in `R_ove`, `R_und`, and prediction count. `R_ali` and `R_occ` ranges overlap. `R_com` has separated three-value ranges under the descriptive criterion stated below. These report-only observations do not establish training equivalence or non-equivalence.

The current-head evaluation-path comparison covers one shared original seed-1 checkpoint. The package and vendor each produce `4,635` predictions; image/category ids and scores match exactly, boxes match at absolute tolerance `0.0001`, all metrics match at absolute tolerance `2e-9`, and both out-of-bounds counts are `1` under the stated `1e-6` rule. This is an evaluation-path prerequisite pass, not full training parity.

## Install

Run commands from the repository root. Keep generated data, logs, checkpoints, converted local pipelines, and evaluation artifacts under `.cache/radm/`.

```bash
uv sync --package radm --extra training
```

Install the `vendor` extra only for original-code parity checks.

```bash
uv sync --package radm --extra training --extra vendor
```

## Scheduler and recipe notes

The effective recipe uses AdamW with learning rate `2.5e-5`, weight decay `1e-4`, batch size `16`, full-model gradient clipping at `1.0`, warmup factor `0.01` for `1,000` optimizer steps, milestones `150,000` and `220,000`, maximum `250,000` optimizer steps, `1,000` diffusion timesteps, `SNR_SCALE=2.0`, `SAMPLE_STEP=1`, `100` proposals, six repeated heads, and FP32 arithmetic.

The scheduler is checked at optimizer-step cadence. The timestep sampler is checked in the fixed-batch and multi-batch traces. EMA and AMP do not apply to the recorded loop. The approved parity configuration uses `num_workers=0`.

The retained S0 topology evidence records that text encoding fields are derived from the selected mapper, with class-mapping and derived-output guards active; `test_s0_radm_topology.py` was part of the retained `23 passed` result against vendor revision `413f87a45760ceac5635b6a08c8047f86478acf5`.

The issue 261 amendment defines the pre-S5 lockstep gate for this model: initial state, RNG and batch alignment, step-1 forward and loss surfaces, and the recorded step-1 gradient tolerance must pass. Natural long-run comparisons are report-only. The amendment is [issue 261 comment 5318097501](https://github.com/creative-graphic-design/design-generators/issues/261#issuecomment-5318097501).

### Before any S5 launch

The launch prerequisites are measured and recorded: the nested S4 stream passes over `3,784` batches and `60,544` images; the mapper oracle matches post-transform XYXY clipping to resized bounds while preserving vendor resize-coordinate truncation; current-head evaluation-path parity passes with `4,635` predictions on each side and equal metrics; the natural `300`-step separate-process self-repeats are bitwise equal within each system; and the synchronized `300`-step lockstep is bitwise equal. Periodic vendor evaluation is disabled during package training; the shipped package config has no vendor evaluator hook. The launch manifest is written before the seed queue and records the source commit, resolved shipped config, evaluator command, checkpoint rule, runtime, worker count, and artifact hashes. The source-commit gate was exercised with a deliberate mismatch dry run and stops before training when the pinned commit differs. Tests marked `vendor_parity` are excluded from regular member-test runs; the CPU regression tests for configuration round-trip and RoI layout run in the regular member suite.

## Seed policy

S0-S4 fixtures use the recorded parity seed and are not training-seed or evaluation-seed results. The retained CGL diagnosis covers paired training labels `1`, `2`, and `3` per system and is invalid-stream evidence, not an S5 result. The shared-weight evaluation-path check uses evaluation seed `1`.

### S3 classification

The separate-process self-repeat (3 steps) `.cache/radm/s3/run-070-cross-process-comparison.json` records package trajectory 1 versus trajectory 1 from a second process as bitwise equal, and the same result for the vendor. The natural `300`-step records in `.cache/radm/s3/run-084-natural-300-20261009/` independently reproduce bitwise within each system across two separate processes: package trajectory rows are identical after removing only timestamps, elapsed-time, and device-label metadata, and vendor trajectory rows are identical under the same comparison. The earlier within-process pair figures are withdrawn because that driver reused state inside one process; they are not evidence of cross-process behavior.

The synchronized lockstep `.cache/radm/s5-preflight/run-071-gpu4-20261008/lockstep-300.jsonl` records initial state bitwise equality and no first divergence over `300` steps. S3 is `natural separate-process self-repeat (300 steps): bitwise equal within package and within vendor; separate-process self-repeat (3 steps): bitwise equal trajectory-1 comparisons for package and vendor; synchronized lockstep: bitwise equal for 300 steps`. This establishes exact agreement for the recorded inputs, runtime, and step population. It does not establish S5 training reproduction or agreement beyond the recorded population.

The final parity work corrected four package operations and pinned each correction with a regression check. The target path now performs post-transform clipping of XYXY target coordinates to the resized image bounds, mirroring Detectron2 `transform_instance_annotations` after `apply_box`, with resize-coordinate truncation preserved; `test_s4_aligned_train_mapper_fixture_matches_vendor` and the nested S4 stream gate pin it. The time path now passes vendor `int64` timesteps directly into the time MLP; `test_time_embedding_keeps_vendor_integer_timestep_path` compares the fixed timestep batch bitwise with the vendor embedding. The bbox-delta path now follows the vendor's indexed `0::4` extraction, pre-exponential `dw` and `dh` clamp, width/height multiplication, and indexed writes into a zero tensor; `test_box_delta_expression_matches_vendor_source` pins that output. The ROI path now preserves the vendor channels-last allocation at the pooling output and fills level-selected rows with `index_put_`; the lockstep regression asserts the vendor and package output stride `[12544, 1, 1792, 256]` and bitwise values. These are package fixes.

The S1-S3 fixtures feed batches through the vendor `dataset_mapper`; they bypass the changed package mapper path, which is exercised by the S4 full-stream comparison and mapper-oracle test. The four fixes and their tests are covered by ancestor commits `49544780e4cd98fd990fc03e08aec9108db5e2a6`, `d1d596db6fab41178a8d60d9bb98a16cb0ad18c5`, `63837415c53d0b14eaaa2fb9c117f816895ebfc8`, and `722bdd55fdeb9c9afbb489e84075a91eef666c30`.
