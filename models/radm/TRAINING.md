# RADM Training

This document records the package-local checks that contributors can rerun before deciding whether RADM full training may be claimed.

## Result at a glance

Text-conditioned CGL evidence is pending. The original RADM mapper splits the full image path at its first dot before deriving the text-feature filename. Earlier runs passed a dotted data-root path, so the original arm silently loaded zero text features with an all-false mask. The S3 real-CGL lockstep and production loss envelope, S4 text comparison, evaluation-path parity, and original 250,000-step A100 results are historical and superseded until rerun with a dot-free visible data-root path. Package evaluation now reads test text features as well. The current recipe sets `trainer.deterministic: false`; its production S3 checks and both arms' 250,000-step S5 runs remain pending.

The retained six-checkpoint diagnosis uses the regenerated fixed equivalent evaluator on invalid-stream runs. Those prediction files predate the five package inference/data-path fixes listed below and were evaluated without source text features, so they are historical diagnostics, not current-head inference evidence. The headline directional shift is in `R_ove`, `R_und`, and prediction count. `R_ali` and `R_occ` ranges overlap. `R_com` has separated three-value ranges under the descriptive criterion stated below. These report-only observations do not establish training equivalence or non-equivalence.

The historical evaluation-path comparison covers one shared original seed-1 checkpoint. It produced `4,635` predictions per side with matching ids, scores, boxes, and metrics, but the source path loaded no text features; this is superseded pending a text-conditioned evaluation-path rerun, not a current prerequisite pass.

## Install

Run commands from the repository root. Keep generated data, logs, checkpoints, converted local pipelines, and evaluation artifacts under `.cache/radm/`.

```bash
uv sync --package radm --extra training
```

Install the `vendor` extra only for original-code parity checks.

```bash
uv sync --package radm --extra training --extra vendor
```

## Data

The approved CGL archive may be stored under `.cache/radm/data/cgl/` with source annotations, images, and text features. For original-code runs, pass a dot-free visible path string to the dataset root; a dot-free symlink alias is valid even when its target contains `.cache`, and the alias must not be resolved before it reaches the vendor mapper. The S5 launcher rejects any data-root component containing a dot. For images that genuinely have no feature file, training uses the vendor's all-padding zero-feature fallback. Package and original-code runs use the source five-label order and the released four-output-class configuration.

### Backbone initialization

The CGL and CGL-v2 training recipes select Detectron2's converted torchvision ImageNet R-50 artifact at the [stable public URL](https://dl.fbaipublicfiles.com/detectron2/ImageNetPretrained/torchvision/R-50.pkl); its SHA-256 is checked before loading. The official [Detectron2 conversion script](https://github.com/facebookresearch/detectron2/blob/main/tools/convert-torchvision-to-d2.py) names `resnet50-19c8e357.pth` as its source and maps the torchvision checkpoint into Detectron2 keys, so the matching torchvision ImageNet V1 tensors are equivalent after that key conversion. The current torchvision `DEFAULT` alias is V2; the distinct Detectron2 `ImageNetPretrained/MSRA/R-50.pkl` artifact uses the MSRA/Caffe weights. Neither is a substitute for the pinned torchvision artifact. The official [TorchVision ResNet-50 weights page](https://docs.pytorch.org/vision/stable/models/generated/torchvision.models.resnet50.html) documents the V1/V2 distinction. The [Detectron2 Model Zoo](https://github.com/facebookresearch/detectron2/blob/main/MODEL_ZOO.md#imagenet-pretrained-models) lists the artifact under [CC BY-SA 3.0](https://creativecommons.org/licenses/by-sa/3.0/), which requires attribution and ShareAlike when redistributing the weights or adaptations; package training downloads it into the local cache and does not commit or republish it. The package maps all `265` ResNet body tensors to package keys and leaves FPN initialization unchanged. RGB input uses pixel mean `[123.675, 116.280, 103.530]` and standard deviation `[58.395, 57.120, 57.375]`, with `STRIDE_IN_1X1=False`, matching the torchvision conversion convention. The default cache path is `.cache/radm/weights/R-50.pkl`; select another path with `model.init_args.pretrained_backbone_weights`.

## Scheduler and recipe notes

The effective recipe uses AdamW with learning rate `2.5e-5`, weight decay `1e-4`, batch size `16`, full-model gradient clipping at `1.0`, warmup factor `0.01` for `1,000` optimizer steps, milestones `150,000` and `220,000`, maximum `250,000` optimizer steps, `1,000` diffusion timesteps, `SNR_SCALE=2.0`, `SAMPLE_STEP=1`, `100` proposals, six repeated heads, and FP32 arithmetic. The package optimizer owns clipping: Lightning keeps `gradient_clip_val=0.0`, and the optimizer runs the automatic-optimization closure before clipping the current full-model gradient once.

The scheduler is checked at optimizer-step cadence. The timestep sampler is checked in the fixed-batch and multi-batch traces. EMA and AMP do not apply to the recorded loop. The approved parity configuration uses `num_workers=0`.

The retained S0 topology evidence records that text encoding fields are derived from the selected mapper, with class-mapping and derived-output guards active; the accepted topology run recorded `23 passed` with artifact `413f87a45760ceac5635b6a08c8047f86478acf5`. The fixed-head S0 initializer-scheme test `test_s0_radm_init_scheme_matches_vendor` compares `445` mapped parameter rows and records `0` mismatches; every package/vendor row uses the same initializer scheme and arguments. The head fix now executes the vendor `xavier_uniform_`, focal-prior, GRAM/final-layer, and time-MLP initialization calls at the same construction point and in the same order, so the earlier initialization call-order deviation is withdrawn.

The pre-S5 lockstep gate requires equal initial state, aligned RNG and batches, matching step-1 forward and loss surfaces, and a passing step-1 gradient tolerance. Natural long-run comparisons are report-only. The gate decision is recorded in the [issue 261 lockstep amendment](https://github.com/creative-graphic-design/design-generators/issues/261#issuecomment-5318097501).

### Before any S5 launch

The earlier S4 image and box stream counts and the natural and synchronized `300`-step comparisons remain historical records, but the vendor data root contained a dot and its text lookup failed. Before S5, rerun the real-CGL lockstep and production loss envelope with `trainer.deterministic: false`, assert non-empty source/package text masks in train and test for S4, and rerun evaluation-path parity with test text enabled. Use one source commit and one dot-free visible data-root string for both S5 arms. Periodic vendor evaluation is disabled during package training; the shipped package config has no vendor evaluator hook. The launch manifest records the source commit, resolved shipped config, evaluator command, checkpoint rule, runtime, worker count, and artifact hashes. Tests marked `vendor_parity` are excluded from regular member-test runs; the CPU regression tests for automatic-optimization clipping, configuration round-trip, and RoI layout run in the regular member suite.

## Seed policy

S0-S4 fixtures use the recorded parity seed and are not training-seed or evaluation-seed results. The retained CGL diagnosis covers paired training labels `1`, `2`, and `3` per system and is invalid-stream evidence, not an S5 result. The shared-weight evaluation-path check uses evaluation seed `1`.

The package and vendor use uniform shuffles with the same sampler behavior, and the accepted aspect-ratio-grouping fix remains covered by the S4 regression code. However, the recorded real-CGL natural and synchronized S3 comparisons used a dotted source data path and do not establish text-conditioned agreement. The S5 statistical design remains three package versus three vendor training seeds, with the range test and seed-spread comparison unchanged.

## Training commands

Run the staged parity checks with the audited runtime used for the final CUDA evidence.

```bash
CUDA_VISIBLE_DEVICES=<device> RADM_REFERENCE_DEVICE=cuda PARITY_REQUIRE=1 UV_FROZEN=1 "$RADM_REFERENCE_VENV/bin/python" -m pytest models/radm/tests/vendor_parity -m "vendor_parity and training" -rs
```

Run both CGL S5 arms from the same source commit and dot-free data-root string. `RADM_CGL_DATA_ROOT` may be a dot-free symlink alias whose target is stored under `.cache`; the launcher passes the alias without resolving it. Repeat for each training seed and use a new output directory for every arm/seed pair.

```bash
set -euo pipefail
export SOURCE_COMMIT="$(git rev-parse HEAD)"
: "${RADM_CGL_DATA_ROOT:?Set this to the visible dot-free CGL data path}"
for SEED in 1 2 3; do
  for ARM in package original; do
    PATH="$RADM_REFERENCE_VENV/bin:$PATH" PYTHONPATH=models/radm/src:lib/traingen/src:lib/traingen-parity/src:lib/laygen/src:lib/posgen/src UV_FROZEN=1 CUDA_VISIBLE_DEVICES=<device> PYTHONUNBUFFERED=1 OMP_NUM_THREADS=1 "$RADM_REFERENCE_VENV/bin/python" models/radm/scripts/train_cgl_s5.py --arm "$ARM" --seed "$SEED" --data-root "$RADM_CGL_DATA_ROOT" --source-commit "$SOURCE_COMMIT" --output-dir ".cache/radm/s5/cgl/$SOURCE_COMMIT/$ARM-seed-$SEED"
  done
done
```

The terminal evaluator must reject any checkpoint whose global step is not `250,000` or whose seed, resolved config path, config SHA-256, or identity metadata does not match its launch manifest.
