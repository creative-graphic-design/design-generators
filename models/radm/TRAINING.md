# RADM Training

This document records the package-local checks that contributors can rerun before deciding whether RADM full training may be claimed.

## Result at a glance

The original RADM mapper derives text-feature filenames from the visible image path, so dots in a data-root path can make valid text features unreachable. Text-conditioned pre-launch checks passed from source commit `4e5c31d44052ae0f8f682c073ba6ab9d940be503`: a 300-step real-CGL lockstep, the three-seed 1,500-update loss envelope for both arms, S4 train/test text parity, evaluation-path parity, and a two-step top-k checkpoint smoke. Six S5 runs (package and original, training seeds 1–3) launched on 2026-11-06 JST from that same commit; terminal checkpoints and evaluation results are pending. Earlier textless CGL S3/S4/evaluation evidence and original S5 results remain below as historical, superseded records.

The retained six-checkpoint diagnosis uses the regenerated fixed equivalent evaluator on invalid-stream runs. Those prediction files predate the five package inference/data-path fixes listed below and were evaluated without source text features, so they are historical diagnostics, not current-head inference evidence. The headline directional shift is in `R_ove`, `R_und`, and prediction count. `R_ali` and `R_occ` ranges overlap. `R_com` has separated three-value ranges under the descriptive criterion stated below. These report-only observations do not establish training equivalence or non-equivalence.

The earlier evaluation-path comparison covers one shared original seed-1 checkpoint. It produced `4,635` predictions per side with matching ids, scores, boxes, and metrics, but the source path loaded no text features. That comparison is superseded by the text-conditioned evaluation-path check recorded below.

## Install

Run commands from the repository root. Keep generated data, logs, checkpoints, converted local pipelines, and evaluation artifacts under `.cache/radm/`.

```bash
uv sync --package radm --extra training
```

Install the `vendor` extra only for original-code parity checks.

```bash
uv sync --package radm --extra training --extra vendor
```

## Data

The approved source for CGL is `creative-graphic-design/CGL-Dataset`, under the [shared source-selection rules](https://github.com/creative-graphic-design/design-generators/blob/main/docs/data-sources.md#shared-source-selection-rules). Its archive may be stored under `.cache/radm/data/cgl/` with source annotations, images, and text features. For original-code runs, pass a dot-free visible path string to the dataset root; a dot-free symlink alias is valid even when its target contains `.cache`, and the alias must not be resolved before it reaches the vendor mapper. The S5 launcher rejects any data-root component containing a dot. For images that genuinely have no feature file, training uses the vendor's all-padding zero-feature fallback. Package and original-code runs use the source five-label order and the released four-output-class configuration.

### Backbone initialization

The CGL and CGL-v2 training recipes select Detectron2's converted torchvision ImageNet R-50 artifact at the [stable public URL](https://dl.fbaipublicfiles.com/detectron2/ImageNetPretrained/torchvision/R-50.pkl); its SHA-256 is checked before loading. The official [Detectron2 conversion script](https://github.com/facebookresearch/detectron2/blob/main/tools/convert-torchvision-to-d2.py) names `resnet50-19c8e357.pth` as its source and maps the torchvision checkpoint into Detectron2 keys, so the matching torchvision ImageNet V1 tensors are equivalent after that key conversion. The current torchvision `DEFAULT` alias is V2; the distinct Detectron2 `ImageNetPretrained/MSRA/R-50.pkl` artifact uses the MSRA/Caffe weights. Neither is a substitute for the pinned torchvision artifact. The official [TorchVision ResNet-50 weights page](https://docs.pytorch.org/vision/stable/models/generated/torchvision.models.resnet50.html) documents the V1/V2 distinction. The [Detectron2 Model Zoo](https://github.com/facebookresearch/detectron2/blob/main/MODEL_ZOO.md#imagenet-pretrained-models) lists the artifact under [CC BY-SA 3.0](https://creativecommons.org/licenses/by-sa/3.0/), which requires attribution and ShareAlike when redistributing the weights or adaptations; package training downloads it into the local cache and does not commit or republish it. The package maps all `265` ResNet body tensors to package keys and leaves FPN initialization unchanged. RGB input uses pixel mean `[123.675, 116.280, 103.530]` and standard deviation `[58.395, 57.120, 57.375]`, with `STRIDE_IN_1X1=False`, matching the torchvision conversion convention. The default cache path is `.cache/radm/weights/R-50.pkl`; select another path with `model.init_args.pretrained_backbone_weights`.

## Scheduler and recipe notes

The effective recipe uses AdamW with learning rate `2.5e-5`, weight decay `1e-4`, batch size `16`, full-model gradient clipping at `1.0`, warmup factor `0.01` for `1,000` optimizer steps, milestones `150,000` and `220,000`, maximum `250,000` optimizer steps, `1,000` diffusion timesteps, `SNR_SCALE=2.0`, `SAMPLE_STEP=1`, `100` proposals, six repeated heads, and FP32 arithmetic. The package optimizer owns clipping: Lightning keeps `gradient_clip_val=0.0`, and the optimizer runs the automatic-optimization closure before clipping the current full-model gradient once.

The scheduler is checked at optimizer-step cadence. The timestep sampler is checked in the fixed-batch and multi-batch traces. EMA and AMP do not apply to the recorded loop. The parity configuration uses `num_workers=0`.

The retained S0 topology evidence records that text encoding fields are derived from the selected mapper, with class-mapping and derived-output guards active; the topology run recorded `23 passed` with artifact `413f87a45760ceac5635b6a08c8047f86478acf5`. The fixed-head S0 initializer-scheme test `test_s0_radm_init_scheme_matches_vendor` compares `445` mapped parameter rows and records `0` mismatches; every package/vendor row uses the same initializer scheme and arguments. The head fix now executes the vendor `xavier_uniform_`, focal-prior, GRAM/final-layer, and time-MLP initialization calls at the same construction point and in the same order, so the earlier initialization call-order deviation is withdrawn.

The pre-S5 lockstep gate requires equal initial state, aligned RNG and batches, matching step-1 forward and loss surfaces, and a passing step-1 gradient tolerance. Natural long-run comparisons are report-only. The lockstep criterion is recorded in the [issue 261 lockstep amendment](https://github.com/creative-graphic-design/design-generators/issues/261#issuecomment-5318097501).

Production CGL runs use `trainer.deterministic: false`; deterministic controls remain enabled for the parity lockstep. The 60.016-second package measurement over updates 301–341 recorded `1.500405` seconds per update and did not meet the [GPU-bound criterion](https://github.com/creative-graphic-design/design-generators/blob/main/docs/training-reproduction.md#gpu-placement). The measurement is `.cache/radm/s5/cgl/prelaunch-4e5c31d/gpu-bound/seed-1-steps300-500.json` (SHA-256 `3b58a296b2f450a201272d7ab34cf494d5e568091a58c6ef00fd7a6f8e91a9e2`), with the run log at `.cache/radm/s5/cgl/prelaunch-4e5c31d/logs/gpu-bound-seed1.log` (SHA-256 `61ae87225c7a2bec62d050cd63e4c5f340aa9142fc106db097fc9b7dba5c06d5`). The package S5 runs for seeds 1–3 proceed under the GPU-bound deviation recorded in the [CGL S5 recipe amendment](https://github.com/creative-graphic-design/design-generators/issues/261#issuecomment-6675591463).

### Pre-launch gates

The current pre-launch gates passed with a shared dot-free visible data-root string and source commit `4e5c31d44052ae0f8f682c073ba6ab9d940be503`. The passing lockstep, loss envelope, text-conditioned loader and evaluation checks, and checkpoint smoke are recorded in Stage Evidence. The 250,000-step S5 outcomes remain pending. Periodic vendor evaluation is disabled during package training; the shipped package config has no vendor evaluator hook. Each launch manifest records source revisions, configuration identity, evaluator and checkpoint rules, runtime versions, CUDA and GPU details, worker and thread counts, data-root hashes, text-feature inventory, and timezone-aware launch time. Tests marked `vendor_parity` are excluded from regular member-test runs; the CPU regression tests for automatic-optimization clipping, configuration round-trip, and RoI layout run in the regular member suite.

## Seed policy

S0-S4 fixtures use the recorded parity seed and are not training-seed or evaluation-seed results. The retained CGL diagnosis covers paired training labels `1`, `2`, and `3` per system and is invalid-stream evidence, not an S5 result. The shared-weight evaluation-path check uses evaluation seed `1`.

The package and vendor use uniform shuffles with the same sampler behavior, and the aspect-ratio-grouping fix remains covered by the S4 regression code. Earlier real-CGL natural and synchronized S3 comparisons used a dotted source data path and remain superseded; the current text-conditioned lockstep and loss envelope are recorded in Stage Evidence. The S5 statistical design remains three package versus three original training seeds, with the range test and seed-spread comparison unchanged.

## Training commands

Run the staged parity checks with the audited runtime used for the final CUDA evidence.

```bash
CUDA_VISIBLE_DEVICES=<device> RADM_REFERENCE_DEVICE=cuda PARITY_REQUIRE=1 UV_FROZEN=1 "$RADM_REFERENCE_VENV/bin/python" -m pytest models/radm/tests/vendor_parity -m "vendor_parity and training" -rs
```

Run both CGL S5 arms from the same source commit and dot-free data-root string. The launcher converts a relative path to an absolute path lexically, then passes that same path to either arm without resolving symlinks; a dot-free alias may point into `.cache`. Before training starts, it requires clean repository and vendor source trees, verifies that the checked-out RADM vendor commit matches the root gitlink, requires annotation-matched text features in both splits and an available CUDA device, and refuses an existing output directory. It writes `manifest.json` before training with both source revisions, arm config and SHA-256, evaluator and terminal-checkpoint rules, runtime versions, CUDA/GPU and thread details, worker count, hashes for the data-root alias and target, per-split feature counts, the original-arm Pillow compatibility module and SHA-256, and a timezone-aware launch time. The tracked `sitecustomize.py` restores `PIL.Image.LINEAR` before Detectron2 imports it in the original training and evaluation processes. Repeat for each training seed and use a new output directory for every arm/seed pair.

```bash
set -euo pipefail
export SOURCE_COMMIT="$(git rev-parse HEAD)"
: "${RADM_CGL_DATA_ROOT:?Set this to the visible dot-free CGL data path}"
for SEED in 1 2 3; do
  for ARM in package original; do
    PATH="$RADM_REFERENCE_VENV/bin:$PATH" PYTHONPATH=models/radm/src:lib/traingen/src:lib/traingen-parity/src:lib/laygen/src:lib/posgen/src UV_FROZEN=1 CUDA_VISIBLE_DEVICES=<device> PYTHONUNBUFFERED=1 OMP_NUM_THREADS=1 "$RADM_REFERENCE_VENV/bin/python" models/radm/scripts/train_cgl_s5.py --arm "$ARM" --seed "$SEED" --data-root "$RADM_CGL_DATA_ROOT" --source-commit "$SOURCE_COMMIT" --output-dir ".cache/radm/s5/cgl/$SOURCE_COMMIT/$ARM-seed-$SEED"
  done
done
```

Package terminal evaluation requires a `package` launch manifest whose training seed, config path and SHA-256, max steps, and checkpoint-rule path match the evaluated run. The manifest's `output_root` must equal the directory containing the manifest, and the resolved checkpoint must match the checkpoint-rule path with `global_step` `250,000`.
